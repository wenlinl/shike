# 食刻 · 磁吸门版硬件设计方案（成本最低版）

> 日期：2026-08-17
> 目标产品形态：一块磁吸屏版，贴在**冰箱门内侧**时开门自动进入连续扫描模式，实时录入放进/取出的食物；需要单品扫描时**取下在门外扫**；平时**贴门外做展示板**。硬件全部重新设计，目标：BOM 成本最低 + 门内扫描时延最低。

---

## 1. 产品形态

单块"磁吸屏版"（约 10×7×2cm，300g 内）：

- **背面**：4 颗 N52 磁铁 + 硅胶垫，内门/外门铁板均可直接吸；
- **正面**：广角摄像头 + 补光灯 + 2.4" 彩屏 + 2 个大物理按键；
- **供电**：内置 1200mAh 锂电 + USB-C 充电（摘下充电，像手机一样 1–2 周充一次）；
- **切换位置**：单手取下换面贴，约 10 秒，无需拆线、无需支架。

## 2. 三个使用场景

| 场景 | 触发 | 交互 | 时延目标 |
|---|---|---|---|
| 门内连续扫描 | 干簧管检测到开门 | 自动连续取景，每件食物经过即抓帧识别，屏幕即时显示"已录入：牛奶×1"；关门后弹出本次汇总一次确认 | 已知品 <0.6s；新品 1.5–2.5s |
| 门外单品扫描 | 按键 / 触摸屏 | 取下对准单品，按一下自动拍照识别，显示品名/日期/保质期 | <1s（已知品） |
| 门外展示板 | 静止待机 | 常显时钟 + 临期提醒 + 今日菜谱，按任意键唤醒 | 唤醒 <0.3s |

## 3. 设计约束与关键决策

### 3.1 冰箱门是法拉第笼（最重要的时序约束）

金属冰箱门关门后对 2.4GHz Wi-Fi 衰减极大。因此**不要设计成"关门也连着云"**：

- **通信窗口 = 开门扫描的时段**：扫描时恰好门开着，此时连 Wi-Fi 上传识别；
- 关门后设备进入低功耗待机，结果先落本地（NVS/flash），下次开门补传；
- 这同时解决电池续航——不需要常连接保活。

### 3.2 低温与凝露

- 主舱位温度 2–8°C，锂电可用（容量略降），**不要放进冷冻室**；
- 镜头用防雾镀膜 + 壳体密封，开机短暂预热（CPU/背光发热）可加速除雾；
- 板件做三防漆，防凝露短路。

### 3.3 湿手场景：不用触屏

冰箱前手指可能湿/冷/有油，触屏体验差且贵。用 **2 个超大物理按键**（扫描 / 确认切换），成本低 ¥8–10，可靠性更高。

### 3.4 低延时 = 双级识别 + 目录缓存

"实时扫描"的关键是别让每件食物都走完整云端链路：

- **第一级（板端，每帧）**：运动检测 + 轻量食品分类（ESP-DL / TFLite Micro），判断"有没有食物、是什么品类（奶/蛋/菜/肉/饮料）"，100–300ms 出结果；
- **第二级（云端，仅最佳帧）**：精确品名 + 保质期 OCR（复用现有 tuvmkt.com /api/scan），异步补全；
- **目录缓存**：首次识别结果（品名 + 保质期天数）写回板端本地目录，同物第二次扫描直接本地命中，<0.6s 免云端——家庭场景绝大多数是重复购买（牛奶、鸡蛋、蔬菜），越用越快；
- **批量队列**：门内连续扫不逐件等确认，先连续抓帧入队，关门后汇总"本次 5 件：放入 4 / 取出 1"一次确认。

### 3.5 成本最低 = 砍外设

单板、单屏、单镜头、单电池；砍掉触屏、SD 卡、音频 codec、双摄像头、e-ink、Linux 板。

## 6. 低延时管线（时延预算）

| 环节 | 耗时 | 说明 |
|---|---:|---|
| 开门唤醒（干簧管中断） | <50ms | 深度睡眠 GPIO 唤醒 |
| 取景 10fps + 运动检测 | 100–200ms | 检测到运动即开始连续抓帧 |
| 最佳帧筛选（清晰度/倾斜/距离） | <100ms | 板端质量门，跳过糊帧 |
| 板端品类分类 | 100–300ms | 已知品类先上屏 |
| 本地目录命中 | <50ms | 同物再扫免云端 |
| 云端识别 + 日期 OCR（仅新品） | 1.5–2.5s | 开门窗口内并行上传，结果异步补到卡片 |
| 关门汇总 | 即时 | 队列一次提交 |

**用户体验**：放进冰箱这个动作本身就要 1–2 秒，识别在放的过程中完成，感知上是"实时"的；已知品基本无感。

## 7. 固件状态机

```text
DISPLAY（门外展示板，低功耗：时钟/临期/菜谱，干簧管或按键唤醒）
 ├─ 检测到贴到内门 + 开门 → SCAN_DOOR
 └─ 按键 → SCAN_SINGLE

SCAN_DOOR（门内连续扫描）
 → 连续取景 10fps → 检出食物 → 抓最佳帧 → 板端分类 → 卡片入队（品类即时显示）
 → 云端异步补全品名/保质期 → 关门 → 汇总页「本次 N 件：放入/取出/跳过」→ 确认提交
 失败帧 → 忽略继续（不打断节奏）

SCAN_SINGLE（门外单品扫描）
 → 按键 → 0.5s 取景 → 自动抓帧 → 板端分类（<0.3s 先显示）→ 云端补全 → 结果页 → 确认

OFFLINE（断网兜底）
 → 板端分类 + 本地目录默认保质期 → 结果标记"待联网确认日期" → 队列本地缓存 → 开门窗口补传
```

## 8. 与现有 T5-E1 的关系：先验证、后改板

**第一步（不花一分钱，用现板验证产品逻辑）**：

1. 把现有 T5-E1 临时固定在冰箱内门（胶带/双面胶），确认最佳安装位：门上部向下 30° 俯视过门通道，镜头到手的距离 30–60cm；
2. 固件把"3 秒倒计时拍照"改成"运动检测自动抓帧"（复用现有板载 GC2145）；
3. 后端加批量队列接口（`POST /api/scan-batch`：一次上传 N 帧，返回 N 条结果）；
4. 实测：广角够不够、补光够不够、凝露情况、关门断网时本地缓存是否正常。

**第二步（验证通过后打样新板）**：

1. ESP32-S3 新板（BOM ¥70–90，可找嘉立创 5 片打样，约 ¥300–500）；
2. 板端轻量分类模型：先可用现成 MobileNet 量化版 + 30 类食品微调；
3. 目录缓存、批量队列、开门检测逻辑移植；
4. 3D 打印试装磁吸外壳 → 验证后开模。

## 9. 验收清单（新板）

- [ ] 内门吸稳，开关门不脱落；取下换外门 ≤10 秒
- [ ] 开门自动进入扫描模式，关门自动汇总
- [ ] 连续放入 3 件不同食品：已知品每件 <0.6s 上屏，无漏检
- [ ] 新品首扫 1.5–2.5s 出结果，日期 OCR 可读
- [ ] 关门断网期间扫描可离线记录，开门后自动补传
- [ ] 待机展示板模式 1–2 周不充电
- [ ] 2–8°C 连续工作 24h 无凝露、无误触发

## 10. 明确不做（本期）

- 不做触屏（湿手场景 + 成本）；
- 不做 SD 卡（flash 缓存够用）；
- 不做 e-ink 双屏（一块 LCD 两用）；
- 不做双摄像头、Linux/NPU 板、本地全量 OCR（成本与功耗不划算）；
- 不做语音播报（蜂鸣器提示音即可）。

## 预留（后续低成本加）

- OTA 升级 + 设备 Token 鉴权（商业化必需）；
- 家人远程查看（复用现有 H5）；
- 门内温湿度长期日志（DS18B20 已含，DHT11 可加 ¥2）。
