# 外置平板（T5-E1）v1 界面与固件改造方案

> 状态：**已实施（2026-08-23，编译验证通过）** ｜ 目标板：T5-E1（SPARKLEIOT T5AI DEV，ST7789 240×320 + CST816X 触控）
> 依据：烧录需求 §4（交互流程）、设计基线 §3（交互与汇总）、后端对接说明 §9（任务下发）
> 一句话：**外置平板从 HW-v0「平板拍照扫描台」改为 HW-v1「门外交互屏」**——不再自己拍照，只做动作下发、结果显示、库存与汇总确认；扫码识别全部由内模组完成。

## 1. 现状（v0，要废弃的部分）

改造前的 `app_xzd.c`（约 1680 行）与旧版 `docs/03-软件/硬件界面参考/` 的 9 个 HTML 为 HW-v0 口径（该页面集已于 2026-08-23 升级为 v1 门外交互屏，v0 拍照流程页面已删除）：

```text
IDLE → [放入|取出] → PREVIEW（相机实时预览 + 3s 半透明倒计时）
     → 平板自动拍照上传 → RESULT / LOW_CONF / NET_FAIL / OFFLINE
```

这与产品文档（HW-v1）冲突：拍照/识别已移到内模组（条码优先 + 语音），平板只保留"门外交互"职责。

**可复用**：屏幕驱动与帧缓冲 UI（RGB565 + alpha）、HZK16 点阵字库、CST816X 触控、HTTPS/TLS 客户端、本地 KV 存储（离线兜底）。

## 2. 目标页面清单（v1）

| 页面 | 内容 | 数据来源 | 触发 |
|---|---|---|---|
| 启动页 | 品牌 + 连接云端 | — | 上电，2–3s 后进待机/离线 |

| 等待扫码页（新） | "已通知内模组，请将食材对准镜头"（语音由内模组播报） | `POST /api/device/task` | 点【放入】/【取出】 |
| 识别结果页（改） | 品名、当天时间、保质期/到期日、建议容器 | 云端最近扫描事件（轮询，接口见 §5 缺口①） | 内模组识别成功 |
| 库存页（新） | 按容器/剩余天数列表，**临期/过期置顶** | `GET /api/items` | 点待机页提醒条 / 入口 |
| 汇总待确认页（新） | 顶部"放入 X / 取出 Y / 中途取出 Z / 未识别 W"；可疑项展开可操作；一键确认或逐条修正 | 汇总接口（契约待定，§5 缺口②） | 关门结算后有可疑项 |
| 断网离线页 | 本地最近库存 + "网络不好" | 本地 KV | 断网 |

说明：

- 待机页两个大按钮沿用现有样式（放入=红渐变实心、取出=白底红描边，触控目标 ≥80px）；
- 识别结果页复刻 v0 的 04/05 页面样式，但数据源从"平板本地上传响应"改为"云端内模组扫描事件"；
- 汇总页布局按[设计基线 §3.4](../02-硬件/设计基线-硬件逻辑梳理.md)：高置信项默认折叠，可疑项高亮展开；触发分级：全高置信→静默入账，有可疑→待确认，异常显著→强调提醒；
- 断网降级按烧录需求 §4.3：平板显示本地最近一次库存与提醒，提示"先不扫描"；内模组断网入队、恢复重传。

## 3. 状态机（v1）

```text
BOOT ──> STANDBY（待机页）
  │         │ 点【放入】/【取出】→ POST /api/device/task
  │         ▼
  │      WAIT_SCAN（等待扫码页，内模组语音播报为主）
  │         │ 轮询云端最近扫描事件
  │         ├─ 成功 → RESULT（识别结果页）→ 自动回 STANDBY
  │         └─ 失败/超时 → 提示"请转一下条码 / 没看清" → 回 STANDBY
  │         ▼
  │      （关门结算，云端生成汇总）
  │         ├─ 无差异 → 静默入账 → STANDBY
  │         └─ 有可疑 → SUMMARY（汇总待确认页）→ 确认/修正 → STANDBY
  └─ 断网 → OFFLINE（本地缓存 + 禁用扫描）→ 恢复联网回 STANDBY
STANDBY ──点提醒条──> STOCK（库存页）──> 回 STANDBY
```

## 4. 数据流与 API 依赖

```text
平板 ──POST /api/device/task──> 云端（保存当前动作 in/out）
内模组 ──GET /api/device/task──> 云端（扫码前取动作，null 默认 in）
内模组 ──POST /api/scan───────> 云端（识别 + 入账 + 写流水）
平板 ──GET /api/items─────────> 云端（库存列表，按容器/剩余天数）
平板 ──GET /api/reminders─────> 云端（临期/过期）
平板 ──GET 最近扫描事件────────> 云端（识别结果同步，缺口①）
平板 ──POST 汇总确认──────────> 云端（缺口②）
```

双模组同步全部走云端（无穿门直连，ADR-008）；平板请求带 `X-Device-Token`。

**接口状态（2026-08-23 已实现，后端 commit `28a89c3`）**：

1. ✅ `GET /api/scan/latest`（§9.1）：内模组最近扫码事件，平板 WAIT_SCAN 每 2–3s 轮询；
2. ✅ `POST /api/summary/confirm`（§9.2）：批次逐条/整体确认，`pending → confirmed`；
3. ✅ `GET /api/summary/pending`（§9.2）：待确认批次与明细，无批次返回 `data:null`。

> 批次产生已定并实现（后端 commit `7838a89`）：云端按开门窗口（相邻扫码间隔 ≤10 分钟）自动结算扫码日志生成批次（§9.3）；内模组关门时 `POST /api/summary/submit` 补充未识别/中途取出并立即结算（§9.4，**固件端待接**）。
> 平板汇总页已接真实 `pending/confirm`（2026-08-23 固件补丁 `apply_net_v2` / `apply_xzd_v1e`，编译通过），演示数据已移除；汇总三通道仅剩"内模组 submit 时机"一个缺口。
