## 1. 结论

- **扫描链路真实可用**：H5 扫描页走真实 `POST /api/scan`（火山方舟视觉模型），低置信不入库；HW-v1 主链路由内模组承担（条码本地解码 + 视觉兜底 + 云端查库，ADR-010）；
- **接口已全部接线，演示数据仅作兜底**：H5 已包含 items / reminders / recipes / shopping-list / members / notifications / catalog / nutrition / trace / shelf-life / consume / auth / family 等接口调用，失败时回退本地演示数据（README 口径：首页 / 库存 / 菜谱 / 我的为演示数据兜底，扫描页为真实识别）；
- **v1 快照的接口缺口已闭环**：`GET /api/shelf-life` 路由已存在，H5 `fetchShelfLife()` 已改调该路由（原"建议保鲜天数回退默认值"Bug 已修复）；nutrition / trace / device / summary / scan-latest 等路由后端均已提供；
- **剩余差距**：① H5 各页从"演示数据兜底"切到全真实数据仍需逐页验证；② 关门结算三通道的"严重差异推送"依赖原生 App / 小程序（SW-v2，见[风险清单](../05-执行/风险清单.md) R3）；③ 快速录入（后端 manual 写入）、收藏偏好、食材履历的完整读写交互仍以演示数据为主。

1. **逐页切真实数据**：以库存为样板，把首页 / 菜谱 / 我的各页从"兜底优先"切换为"真实优先"，并记录接口失败率；
2. **关门结算三通道收口**：外置平板已接真实 `summary/pending` + `summary/confirm`；补齐内模组 `POST /api/summary/submit` 时机（固件端待接）；
3. **SW-v2 推送载体**：原生 App / 小程序启动，解决"严重差异推送"（风险清单 R3）；
4. **快速录入 / 收藏偏好**：后端补 manual 写入与 RecipePreference 读写接口（若产品保留该交互）。
