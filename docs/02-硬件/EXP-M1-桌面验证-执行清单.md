# EXP-M1 桌面验证执行清单

## EXP-01 冰箱门 Wi-Fi 衰减实测

### 前置
- 手机 A：开 2.4G 热点（关 5G）；
- 测信号设备：手机 B（装 Wi-Fi 信号 App）或带 Wi-Fi 的电脑 / ESP32；
- 至少 1 台真实冰箱（测试环境）；有机会追加不同门材质（金属 / 塑料 / 泡沫门）。

### 步骤
1. 手机 A 开热点，记录热点名称；
2. 测信号设备放在**内模组安装位**（门内侧上部 1/4 处），用胶带固定；
3. 按四个状态依次测：门全开 90° / 门半开 45° / 门关闭（密封）/ 门外 1m（对照）；
4. 每个状态测 5 次，记录 RSSI、丢包率、Ping 往返；尝试建立一次 TCP/HTTP 连接；
5. 换冰箱（如有）重复 1–4。

### 记录表（每台冰箱一张）

| 冰箱型号 | 门材质 | 状态 | RSSI (dBm) | 丢包率 | Ping RTT (ms) | 可建立连接 | 备注 |
|---|---|---|---|---|---|---|---|
| 例：海尔 BCD-470 | 金属 | 全开 90° | -58 | 0% | 12 | 是 | |
|  |  | 半开 45° |  |  |  |  | |
|  |  | 关闭 |  |  |  |  | |
|  |  | 门外 1m 对照 |  |  |  |  | |

### 决策
- 关门后 RSSI > -85dBm 且可建立连接 → 架构可加"关门短窗口（0–60s）补传"优化项（不改主架构）；
- 关门后完全不可达 → 维持"离线队列 + 开门窗口同步"主架构（当前设计，无需改动）。

### 产出
结论 + 是否启用关门短窗口补传。

## EXP-02 开门时长与使用节奏统计

### 前置
- 一个真实家庭场景（可让用户/自己记录 2–3 天日常开门）；
- 手机计时（或录像）。

### 步骤
1. 记录 10 次真实开门会话：买菜入库 / 日常取用 / 只看看 三类各若干；
2. 每次记录：开门→关门时长；放入 / 取出 / 中途取出件数；
3. 对放入件：记录每件从"出现在门口"到"放上搁架"的间隔（估测或录像回放）；
4. 备注异常（门开了很久没动、反复开关等）。

### 记录表

| 会话 | 日期时间 | 时长 (s) | 原因 | 放入件数 | 取出件数 | 中途取出 | 单件最长 (s) | 单件最短 (s) | 备注 |
|---|---|---|---|---|---|---|---|---|---|
| 1 |  |  | 买菜入库 |  |  |  |  |  | |
| 2 |  |  | 日常取用 |  |  |  |  |  | |
| … |  |  |  |  |  |  |  |  | |
| 10 |  |  |  |  |  |  |  |  | |

### 决策
- 平均开门 <20s 且件数 >5 → 事件采集需"并行上传 + 本地缓存"（当前架构已按此设计，确认即可）；
- 平均开门 >60s → 串行上传可行，可简化上传策略；
- 单件经过时间分布 → 供事件检测的抓拍窗口定参。

### 产出
开门节奏分布 + 事件采集窗口参数建议。

## EXP-05 云端识别时延定标

### 前置
- shike.live 后端可访问（或本地起后端）；
- 20 张代表性测试图：条码清晰 / 条码模糊 / 反光 / 无码散装 / 多件同框 / 低光照 各若干张；
- 上传脚本（curl 或 python，循环调用 POST /api/scan）。

### 步骤
1. 每张图上传 1 次，记录：上传耗时、识别耗时、总耗时、返回 code、置信度；
2. 对失败请求单独记录失败原因（超时 / 5xx / 低置信）；
3. 统计 P50 / P95 / 失败率，按图片特征分组看差异。

### 记录表

| 样本 | 图片特征 | 上传耗时 (ms) | 识别耗时 (ms) | 总耗时 (ms) | code | 置信度 | 备注 |
|---|---|---|---|---|---|---|---|
| 1 | 条码清晰 |  |  |  |  |  | |
| 2 | 反光 |  |  |  |  |  | |
| … |  |  |  |  |  |  | |
| 20 | 无码散装 |  |  |  |  |  | |

### 决策
- P95 <3s → 门内连续扫描 / 批量场景成立；
- P95 ≥3s → 管线加板端预分类或本地目录命中（先出品类再补精确）；
- 同时定标：条码场景 vs 无码场景的时延差异（用于播报分级）。

### 产出

## EXP-18 冰箱尺寸与视野覆盖实测

### 前置
- 5 种主流冰箱（两门 / 对开门 / 法式多门，可借或卖场测量）；
- 手机（有广角模式，记录等效 FOV）+ 量尺 + 拍照。

### 步骤
1. 每台冰箱记录：冷藏室内腔高 / 宽 / 深、层数、层间距、各层前缘到门内侧距离；
2. 手机固定在门内侧 1/4、1/3、1/2 三个安装高度（模拟内模组）；
3. 每个高度 × 三种朝向（垂直门板 / 偏门口 15° / 偏门口 30°）各拍一张；
4. 对每张照片判断：门口扫码位（用户站门口举食材高度，约 0.8–1.2m）是否在视野内；最下层前缘是否可见；逐层记录可见深度占比。

| 冰箱型号 | 类型 | 内腔高 (cm) | 内腔宽 (cm) | 内腔深 (cm) | 层数 | 层间距 (cm) |
|---|---|---|---|---|---|---|
| 例：BCD-470 | 对开门 | 82 | 60 | 55 | 4 | 20 |

| 安装高度 | 朝向 | 扫码位可见 | 最下层前缘可见 | 第 1 层可见深度% | 第 2 层% | 第 3 层% | 第 4 层% |
|---|---|---|---|---|---|---|---|
| 上 1/4 | 垂直 |  |  |  |  |  |  |
| 上 1/4 | 偏门口 15° |  |  |  |  |  |  |
| 上 1/4 | 偏门口 30° |  |  |  |  |  |  |
| 上 1/3 | … |  |  |  |  |  |  |

### 决策
- 找到"扫码位可见 + 各层前缘可见"的安装高度 / 朝向组合；
- 垂直 FOV 60° 覆盖 ≥90% 目标区域 → 镜头 FOV 硬参数与安装位定型；
- 若最下层始终不可见 → 明确"最下层靠用户扫码 + 事件兜底"，并评估是否需要下调"覆盖 ≥90%"目标。

### 产出
安装位推荐（高度 + 朝向）+ FOV 硬参数确认 + 各层可见深度数据（供事件检测区域划分）。
