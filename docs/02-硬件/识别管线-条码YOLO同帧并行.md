# 识别管线 · 条码 + YOLO 同帧并行（设计说明）

> 状态：设计已定，代码未动（06 示例待办）｜ 关联：ADR-010、[设计基线 §2.3](./设计基线-硬件逻辑梳理.md)、[成品规格书 Q1](./成品规格书-HW1.md)、EXP-11
> 识别对象口径：**食物 / 食材**（无"零食"品类；容器枚举中的"零食柜"另议，见文末）

## 1. 目标

同一帧画面**同时**做两路识别，按决策树合并，一次扫描出一个动作：

```text
条码解码成功        → 精确品名（查库，含保质期）
检测到条码但解码失败 → 语音"请转一下条码"（<2s 重试）
无码 / 条码被遮     → 走视觉识别
视觉置信度 ≥85%     → 播品类名入账
视觉置信度 <85%     → "没看清再试一次"，连续失败进汇总页
```

硬指标：本地 YOLO ≤500ms（可接受 ≤800ms）、mAP ≥85%（商用）；条码 ms 级。

## 2. 帧管线：统一 RGB565，一帧三用

```text
esp_camera_fb_get() → RGB565 帧（VGA 640×480 ≈ 614KB，PSRAM）
   ├─ ZXing::ReadBarcodes(RGB565)     约 10–50 ms
   ├─ YOLO 推理（INT8，输入 192/224）  约 300–700 ms（瓶颈）
   └─ fmt2jpg(RGB565→JPEG) 上传兜底    约 50–100 ms
   结果合并 → 播报 / 入账 / 云端查库
```

要点：

- **RGB565 是"同时"的前提**：ZXing 原生支持 RGB565 输入、YOLO 需要 RGB、fmt2jpg 支持 RGB565 转 JPEG，一帧同时喂三路，零格式切换；
- 顺带解决现有矛盾：04 用灰度、05 用 JPEG、03 灰度帧差，各自独立烧录；统一 RGB565 后条码 / YOLO / 上传可共用一个主循环；
- 顺序执行整条链路约 ≤1s，满足"扫一下出结果"；双核并行（第三节）只是优化项。

## 3. 双核分工（ESP32-S3 双核 240MHz）

| 方案 | 做法 | 代价 | 建议 |
|---|---|---|---|
| A 顺序执行（先落地） | 单任务：抓帧 → ZXing → YOLO → 上传 | 简单可靠，~1s | ✅ 06 示例先按此 |
| B 双核并行（优化项） | core0 主循环（抓帧/条码/网络/音频/队列）；core1 FreeRTOS 任务跑 YOLO（`xTaskCreatePinnedToCore`），队列传帧指针、PSRAM 缓冲复用 | 省 200–400ms；需处理帧生命周期与优先级 | 功能验收后做，不做也达标 |

## 4. 模型选型与量化路径

- **MVP 形态用分类器，不一定要 YOLO**：识别对象是"单件食材对准镜头"，品类级识别（MobileNetV2 / EfficientNet-Lite，INT8，输入 192/224）就够，板端实测约 100–300ms；
- 若后续要"门内被动抓拍、画面多物 + 定位"，再升级检测模型 **YOLOv5n / YOLOv8n（INT8，输入 192–320）**，板端约 300–700ms（需实测）；
- 板端框架二选一：
  - **ESP-DL 2.x**（乐鑫官方，INT8 + S3 向量加速，TVM 转换链成熟）——性能优先；
  - **TFLite Micro**（生态大、算子兼容好，社区资料多）——开发速度优先；
  - 建议先 TFLite Micro 跑通 demo，性能不达标再切 ESP-DL；
- 量化：INT8 PTQ，校准集 100–300 张；模型 + 固件控制在 8MB Flash 内（小模型约 0.5–1.5MB）。

## 5. 数据集：现成方案（回答"有现成的吗"）

**结论：有"半成品"，没有"开箱即用的家庭冰箱食材模型"。** 最优路径 = 公开集预训练 / 迁移 + 自拍微调，工作量可控。

| 现成资源 | 内容 | 对项目的价值 |
|---|---|---|
| `ibrahimdaud/raw-food-recognition`（Hugging Face） | **90+ 类生鲜食材**，含单标签 / 多标签预训练模型 | 最对口：生鲜食材（raw food）品类起点，可迁移 / 蒸馏 |
| FoodSeg103 / FoodSeg195 | 103 / 195 类**食材级**分割，7118 张（西餐场景） | 食材类别覆盖广，作迁移学习或标签蒸馏 |
| Food-101 / AI4Food-NutritionDB（FruitVeg-81 等） | 101 类食物 / 81 类蔬果 | 通用预训练基线 |
| MM-Food-100K / ConvNeXt-Food-CLF-75 | 4000+ 食材标签大集 + 预训练权重 | 迁移学习底座（云端 / 离线蒸馏） |
| ChineseFoodNet | 208 类中餐**成品菜** 18 万张 | 参考价值低（菜肴 ≠ 食材），个别类别可复用 |

策略：

1. **先定品类口径**（产品侧）：MVP 15–30 类即可（牛奶、鸡蛋、苹果、西红柿、土豆、猪肉、鸡胸、豆腐、酸奶……）；
2. **公开集预训练 / 蒸馏**：用 raw-food 或 FoodSeg 数据训出小模型（Google Colab 免费 GPU 够训 MobileNetV2 / YOLOv5n）；
3. **EXP-11 自拍微调 + 校准**：手机拍冰箱内照片，每类 50–100 张（共 1000–2000 张）→ 微调 + INT8 校准。公开集多为桌面 / 西餐场景，与"冰箱内灯光、收纳袋、俯拍"有**域差**，这一步不能省，但量级已从"从零标注"大幅缩小；
4. **低置信兜底**：云端多模态精识别（doubao 视觉，项目已具备），板端模型只负责常命中品类。

- 依赖：品类口径清单（产品侧）、手机采集（**不依赖硬件**，可与冲刺并行）、Colab 训练环境、TFLite / ESP-DL 工具链、真机（D8 前后到货）；
