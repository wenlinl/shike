# 食刻 · 后端对接说明

> 日期：2026-08-16 ｜ 状态：✅ 已上线 tuvmkt.com（替换 workshop 应用），接口与数据库 v3 均已线上验证
> 线上地址：https://tuvmkt.com/api/*（health / scan / items / reminders / members / recipes / shopping-list / notifications / catalog / consume / device/heartbeat / device/state）
> 数据库：SQLite（服务器容器 /app/data/app.db，Docker 卷持久化），v3 共 15 张表，已含种子数据与真实扫描数据

## 1. 架构

```text
T5-E1 固件（copy 工程 app_xzd）
  │  HTTPS multipart POST /api/scan（图片 + deviceId/action/container/timestamp）
  ▼
后端（midyear-workshop 工程 · 复用其服务器/域名/火山方舟 Key）
  │  保存图片 → 火山方舟视觉模型 doubao-seed-2-1-turbo-260628 识别
  ▼
SQLite（FoodItem 当前库存 + ScanLog 流水）→ 扁平 JSON 返回固件
  │
  ▼
软件端：网页大屏 / H5 / App
  GET /api/items（库存按容器） · GET /api/reminders（临期/过期） · PATCH /api/items/[id]（改容器）
```

## 2. 接口契约

### POST /api/scan（固件上传，公开）

multipart/form-data：

| 字段 | 说明 |
|---|---|
| `image` | JPEG（640×480，30–60KB），filename=scan.jpg |
| `deviceId` | 如 `xzd-t5e1-001` |
| `action` | `in`（放入）\| `out`（取出） |
| `container` | 冰箱 \| 零食柜 \| 药盒 \| 调料柜 \| 主食柜 |
| `timestamp` | `YYYY-MM-DD HH:mm:ss`（UTC，可为空） |

响应（扁平 JSON，固件解析这些键）：

```json
{"code":0,"name":"光明鲜牛奶","scannedAt":"2026-08-15 23:22:00","expiryDate":"2026-08-17","daysLeft":2,"suggestedContainer":"冰箱","confidence":0.92,"note":""}
```

- `code!=0` 或 HTTP 非 200 → 固件显示“网络不好请重试”；
- `name` 为空 / `confidence<0.50` → 固件走 LOW_CONF，提示“没看清，重新对准再拍”；
- 后端自动：保存图片 → ARK 视觉识别 → 更新 FoodItem（in 加数量 / out 减数量，减到 0 删除）→ 写 ScanLog。

### GET /api/items?container=冰箱

```json
{"code":0,"items":[{"id":"...","name":"光明鲜牛奶","category":"乳制品","container":"冰箱","quantity":1,"expiryDate":"2026-08-17","scannedAt":"...","daysLeft":2,"confidence":0.92,"note":"","status":"soon"}]}
```

按容器筛选、剩余天数升序；`status` = normal / soon（≤3 天）/ expired。

### PATCH /api/items/[id]

```json
{"container":"零食柜"}
```

手动修改容器分类。

### GET /api/reminders

```json
{"code":0,"soon":[{"id":"...","name":"...","container":"冰箱","quantity":1,"expiryDate":"2026-08-17","daysLeft":2}],"expired":[]}
```

## 3. 数据库模型（Prisma / SQLite）

- `FoodItem`：当前库存（`@@unique([name, container, deviceId])`，in 加数量 / out 减数量）；
- `ScanLog`：每次扫描流水（最近记录 / 统计）。

### 3.1 数据库需求（v3 · 按最新软件端 食刻-H5手机端.html 对齐）

最新软件端的页面与数据面：

| 页面 / 模块 | 用到数据 | 支撑表 |
|---|---|---|
| 首页：冰箱总览、保鲜提醒、今日推荐、购物清单预览、家庭共享 | 库存 KPI、临期、推荐菜、清单、成员数 | FoodItem、Recipe、ShoppingListItem、Member |
| 扫描：摄像头识别 → 确认录入 → 同步家庭成员 | 识别结果（品名/建议保鲜天数/置信度/建议容器）、录入人 | FoodCatalog、FoodItem、ScanLog、Member |
| 库存：搜索、品类筛选、排序、食材卡片（录入人/时间/到期/存放状态/标签） | 库存明细 | FoodItem（含 recordedBy/recordMethod/keepDays/storage/label） |
| 菜谱：当前可用食材、今日推荐、更多推荐、口味偏好、收藏 | 菜谱库 + 库存匹配 + 偏好 | Recipe、RecipePreference、Member.preferences |
| 我的：成员管理、购物清单、收藏、通知设置、营养档案、关于 | 成员/清单/通知/营养 | Member、ShoppingListItem、Notification、ReminderSetting |
| 食材履历 / 追溯记录 | 来源、产地、批次、冷链、检测报告 | FoodTrace |
| 通知中心（未读 + 跳转） | 站内通知列表 | Notification |
| 营养档案（蛋白质/维C/膳食纤维/钙） | 库存与消耗的营养聚合 | FoodCatalog.nutrition + ConsumptionLog 计算 |
| 月度统计（本月省下金额、浪费、成员录入次数） | 消耗/过期记录、流水聚合 | ConsumptionLog、ScanLog |

### 3.2 表清单（v3）

| 表 | 用途 | 关键字段 |
|---|---|---|
| `FoodItem` | 当前库存（已有，需扩字段） | + `recordedBy`（录入成员）、`recordMethod`（camera/manual）、`keepDays`（建议保鲜天数）、`storage`（保鲜中/冷藏/冷冻/常温）、`label`（如“建议尽快喝”） |
| `ScanLog` | 扫描流水（已有，需扩字段） | + `recordedBy`、`recordMethod`、`keepDays` |
| `Member` | 家庭成员（管理员/成员、头像、负责品类） | name、role、avatar、responsibleCategory、preferences（JSON：口味标签） |
| `Device` | 设备元数据 | deviceId、name、memberId（绑定人）、lastSeenAt |
| `Container` | 容器管理（可自定义） | name、icon、sort、builtIn |
| `FoodCatalog` | 识别知识库（自动分类一致 + 营养 + 保鲜建议） | name、category、emoji、keepDays、defaultExpiryDays、suggestedContainer、aliases、nutrition（JSON）、source（ai/manual）、correctedAt |
| `FoodTrace` | 食材履历 / 追溯 | itemId、source（购买渠道）、origin（产地）、batch、coldChain、report（检测）、inTime |
| `ShoppingListItem` | 购物清单 | name、qty、unit、done、suggested（AI 建议）、source（manual/expiry/recipe）、boughtAt |
| `Notification` | 通知中心（站内） | type（expiry/recipe/member/shop/system）、title、desc、unread、view（跳转目标） |
| `ReminderRecord` | 定时推送幂等去重 | type、scheduledFor、payload、pushedAt（`@@unique([type, scheduledFor])`） |
| `ReminderSetting` | 通知/提醒设置 | key/value（JSON：开关、时间、临期阈值） |
| `ConsumptionLog` | 消耗 / 过期 / 浪费记录（统计与推荐输入） | name、reason（consumed/wasted/expired）、quantity、memberId、note |
| `Recipe` | 菜谱库（智能推荐） | name、emoji、grad、tag、timeMin、desc、nutr、ingredients（JSON：name/qty/status 有缺）、steps（JSON）、tags（JSON） |
| `WeeklyMealPlan` | 周度菜谱计划 | weekStart、date、recipeId、status（planned/done/skipped） |
| `RecipePreference` | 收藏 / 评分 / 做过次数 | recipeId、liked、rating、timesCooked、lastCookedAt |

### 3.3 示例（Prisma 模型，v3）

```prisma
model Member {
  id                   String   @id @default(cuid())
  name                 String   @unique
  role                 String   @default("member") // admin | member
  avatar               String?
  responsibleCategory  String?
  preferences          String?  // JSON：["清淡","家常"]
  createdAt            DateTime @default(now())
}

model Device {
  id         String    @id @default(cuid())
  deviceId   String    @unique
  name       String?
  memberId   String?
  lastSeenAt DateTime?
  createdAt  DateTime  @default(now())
}

model Container {
  id        String   @id @default(cuid())
  name      String   @unique
  icon      String?
  sort      Int      @default(0)
  builtIn   Boolean  @default(false)
  createdAt DateTime @default(now())
}

model FoodCatalog {
  id                 String   @id @default(cuid())
  name               String   @unique
  category           String?
  emoji              String?
  keepDays           Int?     // 建议保鲜天数（扫描页展示）
  defaultExpiryDays  Int?
  suggestedContainer String?
  aliases            String?  // JSON 数组
  nutrition          String?  // JSON：{ protein, vitaminC, fiber, calcium }
  source             String   @default("ai") // ai | manual
  correctedAt        DateTime?
  createdAt          DateTime @default(now())
  updatedAt          DateTime @updatedAt
}

model FoodItem {
  id           String    @id @default(cuid())
  deviceId     String
  memberId     String?   // 录入成员
  name         String
  category     String?
  emoji        String?
  container    String
  quantity     Int       @default(1)
  recordMethod String    @default("camera") // camera | manual
  keepDays     Int?      // 建议保鲜天数
  storage      String?   // 保鲜中 | 冷藏中 | 冷冻 | 常温
  label        String?   // 如“建议尽快喝”
  scannedAt    DateTime
  expiryDate   DateTime?
  daysLeft     Int
  confidence   Float
  note         String?
  imagePath    String?
  createdAt    DateTime  @default(now())
  updatedAt    DateTime  @updatedAt

  @@unique([name, container, deviceId])
  @@index([container])
}

model FoodTrace {
  id        String   @id @default(cuid())
  itemId    String   @unique
  source    String?  // 盒马鲜生…
  origin    String?  // 产地
  batch     String?
  coldChain String?  // 冷链说明
  report    String?  // 检测报告
  inTime    DateTime?
  createdAt DateTime @default(now())
}

model ShoppingListItem {
  id        String    @id @default(cuid())
  name      String
  qty       Int       @default(1)
  unit      String?
  done      Boolean   @default(false)
  suggested Boolean   @default(false)
  source    String    @default("manual") // manual | expiry | recipe
  boughtAt  DateTime?
  createdAt DateTime  @default(now())
}

model Notification {
  id        String   @id @default(cuid())
  type      String   // expiry | recipe | member | shop | system
  title     String
  desc      String?
  unread    Boolean  @default(true)
  view      String?  // 跳转目标：remind / recipe:0 / inv / shop / members …
  createdAt DateTime @default(now())
}

model ReminderRecord {
  id           String    @id @default(cuid())
  type         String
  scheduledFor DateTime
  payload      String?
  pushedAt     DateTime?
  createdAt    DateTime  @default(now())

  @@unique([type, scheduledFor])
}

model ReminderSetting {
  id    String @id @default(cuid())
  key   String @unique
  value String // JSON
}

model ConsumptionLog {
  id        String   @id @default(cuid())
  name      String
  reason    String   // consumed | wasted | expired
  quantity  Int      @default(1)
  memberId  String?
  note      String?
  createdAt DateTime @default(now())
}

model Recipe {
  id          String   @id @default(cuid())
  name        String   @unique
  emoji       String?
  grad        String?
  tag         String?
  timeMin     Int?
  desc        String?
  nutr        String?  // JSON
  ingredients String   // JSON：[{ name, qty, status: 有|缺 }]
  steps       String?  // JSON 数组
  tags        String?  // JSON 数组
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
}

model WeeklyMealPlan {
  id        String   @id @default(cuid())
  weekStart DateTime
  date      DateTime
  recipeId  String
  status    String   @default("planned")
  createdAt DateTime @default(now())

  @@unique([date, recipeId])
}

model RecipePreference {
  id           String    @id @default(cuid())
  recipeId     String    @unique
  liked        Boolean   @default(false)
  rating       Int?
  timesCooked  Int       @default(0)
  lastCookedAt DateTime?
  updatedAt    DateTime  @updatedAt
}
```

### 3.4 落地优先级

- **第一批（软件端页面直接需要）**：`Member`、`FoodCatalog`、`ShoppingListItem`、`Notification`、`ConsumptionLog`、`Device`、`Container`，并给 `FoodItem`/`ScanLog` 扩 `recordedBy`/`recordMethod`/`keepDays`/`storage`/`label` 字段；
- **第二批（菜谱与营养演示）**：`Recipe`（预置种子菜谱）、`WeeklyMealPlan`、`RecipePreference`、`FoodTrace`；
- **第三批（定时推送）**：`ReminderRecord`、`ReminderSetting`。

### 3.5 硬件交互侧（数据库 / 后端同样要考虑）

| 硬件行为 | 后端 / 数据库设计 |
|---|---|
| 设备在线状态（Wi-Fi 链路） | `Device` 表（deviceId、name、firmwareVersion、memberId、lastSeenAt）；新增 `POST /api/device/heartbeat` 更新最后在线（>5 分钟未上报视为离线） |
| 扫描上报（放入/取出） | `POST /api/scan`（已有）：multipart → 识别 → `FoodItem`/`ScanLog`；响应加 `keepDays`（固件解析器忽略未知字段，兼容） |
| 待机屏显示临期 / 过期提醒 | `GET /api/device/state?deviceId=`：返回该设备视角的临期/过期列表 + 最近识别结果（固件可离线缓存的兜底数据） |
| 设备本地库存计数与云端一致性 | **以后端为准**：`/api/scan` 响应可附 `stockTotal`（该设备当前总件数）；固件本地 KV 仅作离线兜底展示 |
| 温度传感器（DS18B20，可选） | 新增 `TemperatureLog`（deviceId、tempC、readAt），由心跳带上或独立上报；异常触达 `ReminderRecord(type=temperature)` |
| 设备诊断 / UART 日志 | 新增 `DeviceLog`（deviceId、event、msg、createdAt）；固件 `[XZD]` 事件（LINK_UP/SCAN_START/SCAN_OK/LOW_CONF/OFFLINE）可经心跳附带上报，便于路演展示“设备在线记录” |
| 设备与成员绑定 | `Device.memberId`：设备归属成员，扫描默认录入人 = 绑定成员 |
| 安全说明 | 固件 TLS no-verify、无鉴权 → `/api/scan`、`/api/device/*` 原型阶段公开；上线前需加设备级鉴权（如设备 Token） |

```prisma
model Device {
  id              String    @id @default(cuid())
  deviceId        String    @unique
  name            String?
  firmwareVersion String?
  memberId        String?
  lastSeenAt      DateTime?
  createdAt       DateTime  @default(now())
}

model DeviceLog {
  id        String   @id @default(cuid())
  deviceId  String
  event     String   // LINK_UP | SCAN_START | SCAN_OK | LOW_CONF | OFFLINE ...
  msg       String?
  createdAt DateTime @default(now())

  @@index([deviceId, createdAt])
}

model TemperatureLog {
  id        String   @id @default(cuid())
  deviceId  String
  tempC     Float
  readAt    DateTime
  createdAt DateTime @default(now())

  @@index([deviceId, readAt])
}
```

## 4. 环境变量（部署时写入服务器 .env）

```text
ARK_BASE_URL=https://ark.cn-beijing.volces.com/api/v3
ARK_VISION_MODEL=doubao-seed-2-1-turbo-260628
ARK_VISION_API_KEY=<支持视觉的方舟 Key>   # 优先；回退 ARK_API_KEY
```

> 注意：项目原 `ARK_API_KEY`（deepseek 文本模型）不支持图片；视觉识别必须用 `ARK_VISION_API_KEY`（read-image 那把 46 位 key）。密钥不写入本文档。
