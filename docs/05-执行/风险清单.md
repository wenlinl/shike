| R4 | **esp32-camera 与 XIAO / Arduino 库兼容性**：esp32 包版本与 esp32-camera 分支不匹配可能编译失败 | 样机第一步卡住 | 中 | 中 | 严格按 Seeed Wiki 版本组合；先跑官方拍照示例再写业务代码 |
| R5 | **量化精度损失**：INT8 量化后 30 类食材 mAP 可能掉 3–8%，≥85% 目标有风险 | 视觉兜底精度 | 中 | 中 | 量化感知训练 + 数据集质量优先（EXP-11 硬验收）；不达标 → 协处理器 + FP16 推理，**保证 mAP ≥85%** |

## 2. 硬件风险

| # | 风险 | 严重度 | 概率 | 缓解 |
|---|---|---|---|---|
| H1 | XIAO 摄像头占用 GPIO10/39/40，外设引脚冲突 | 高 | 低 | 已修正：外设用 GPIO1/2/3/5/6/7，以官方 Wiki 为准 |
| H2 | XIAO 出厂无排针，零基础无法接线 | 高 | 已消除 | BOM 必加 XIAO 扩展板（A2） |
| H3 | 电池供电时扩展板 5V 引脚无输出（VBUS 仅 USB 供电时有）→ 功放无声 | 中 | 中 | 样机用 USB 供电；电池模式功放改接 3V3（功率略小） |
| H4 | USB 供电不足（摄像头 + Wi-Fi + 功放同开）→ 重启 | 中 | 中 | 用带数据线 + 电脑 USB 直连 / 5V1A 电源；分时操作（识别时播报） |
| H5 | 面包板 / 杜邦线接触不良 → 偶发故障 | 中 | 中 | 每步验收 + 排障表；接头压紧、避免悬空 |
| H6 | 光敏检测依赖冰箱灯：灯坏 / 暗光误判 | 低 | 低 | 样机手动模拟；成品保留光敏 + 可加按键触发兜底 |
| H7 | T5-E1 HTTPS GET（拉库存）未实测（现有固件只验证过 POST） | 中 | 低 | 联调第一个用例先验证 GET + JSON 解析 |
| H8 | XIAO 仿品 / 扩展板不兼容 | 中 | 低 | 官方店 / 立创购买 |
| H9 | XIAO Sense microSD 槽与摄像头 / 外设共用引脚（SD 需确认） | 中 | 中 | 样机先不启用 SD（目录 / 队列存 PSRAM），SD 后置确认 |
| H10 | 摄像头供应链：OV2640 已停产（2009 年 EOL），市面均为库存 / 拆机 / 二次封装货，批次品质不可控 | 高 | 中 | 已决策：样机用新批次 XIAO Sense（OV3660），定焦降级目标改 OV3660；量产主选 OV5640 AF。GC2145 作为 pin-to-pin 工业替代第二备选 |

## 4. 小模型风险（重点）

| # | 风险 | 严重度 | 概率 | 缓解 |
|---|---|---|---|---|
| M1 | **推理时延 100–300ms 目标不现实**（真实 300–800ms） | 高 | 高 | 目标改为"实测后定，≤800ms 可接受"；板端轻量分类替代检测；云端精识别 |
| M2 | 30 类食材数据集不足 / 标注质量差 → mAP <85% | 高 | 中 | EXP-11 数据集先行（1000 张起，覆盖光照 / 角度 / 遮挡）；品类粒度放宽 |
| M3 | INT8 量化精度损失（3–8%） | 中 | 中 | 量化感知训练；阈值按品类级容错 |
| M4 | 品类体系与云端 / 条码查库不一致 | 低 | 低 | 统一 FoodCatalog 品类树（设计工作） |
| M5 | 模型 + 字库 + 固件塞不进 N32R8 Flash | 低 | 低 | N32R8 32MB 已确认，空间充足；必要时 SD 外置 |

> **关键判断**：样机阶段**先跑通"拍照 → 云端识别"链路**（现有 shike.live 已具备），本地 YOLO 作为第二阶段优化。这样即使本地模型不达标，产品核心链路依然可用（云端识别 P95 3s 可接受于样机演示）。
