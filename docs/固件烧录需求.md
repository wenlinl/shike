# 「食刻」固件开发需求文档（给写烧录程序的 AI）

> 目标：在 T5-E1（SPARKLEIOT T5AI DEV）上实现「放入 / 取出」交互 + 3 秒倒计时拍照 + 照片上传云端解析，并把结果展示在屏幕。
> 起点工程：`/Users/lwl/TuyaOpenIDE/projects/copy`（已是「点按拍照」样板：GC2145 实时预览上屏 + 触控定格 + UART0 上报，直接在其上改造）。

## 1. 硬件与开发环境

| 项 | 值 |
|---|---|
| 主板 | T5-E1（SPARKLEIOT T5AI DEV），T5AI 平台，8MB Flash / 16MB PSRAM |
| 屏 | ST7789 240×320 触控彩屏（SPI0）；触控 CST816X（I2C1） |
| 摄像头 | 板载 GC2145 DVP（640×480 @15fps 预览） |
| 音频 | 板载 codec + 功放（spk_en GPIO7） |
| 按键 | GPIO8（低有效） |
| 字体 | 16×16 GB2312 点阵（HZK16）+ 8×16 ASCII；**禁止矢量 TTF / 抗锯齿**（详见 §7） |
| 工程 | `copy`（`source/embedded/src/app_photo.c`：预览 + 触控定格 5s） |
| 构建 / 烧录 | `tos.py build`；`tyutool_cli write -d t5 -f copy_QIO_1.0.0.bin -p <port> -b 460800` |

## 2. 交互流程（核心需求）

### 2.1 待机页

- 屏幕显示两个大按钮：**【放入】** 与 **【取出】**（可叠加显示临期 / 过期提醒文字）。

### 2.2 点【放入】→ 入库流程

1. 进入拍照预览：**背景 = 实时摄像头画面**（GC2145 预览上屏，参考 `app_photo.c`）；
2. 启动 **3 秒倒计时**：
   - 屏幕中央显示大号倒计时数字 **3 → 2 → 1**；
   - **数字为半透明**（透明度高，能看到背后实时画面）；
   - **数字占屏幕约一半**（240×320 屏，数字区域建议约 120×160 居中，字号最大可用）；
3. 倒计时归零 → **自动拍照**（抓当前帧）→ 板载音频“咔嚓”一声；
4. **照片实时上传云端**（见 §3 API 契约）；
5. 等待解析（超时建议 15s，显示“正在识别…”）；
6. 收到结果 → 屏幕显示：**品名、当天日期时间、保质期 / 到期日、建议容器**；
7. 用户确认 → 库存 +1 → 回待机页。

### 2.3 点【取出】→ 出库流程

- 与「放入」对称：拍照预览 → 3 秒半透明大数字倒计时 → 拍照上传 → 显示识别结果 → 确认后库存 -1；
- （若需求后续改为「列表选择取出」，以 PRD 最终版为准，固件留好入口。）

### 2.4 失败与兜底

- 上传失败 / 超时：屏幕提示“网络不好，请重试”，不丢本次动作，可重拍；
- 识别结果低置信：屏幕显示“没看清，请重新对准再拍”，不写入库存；
- 断网：显示本地最近一次库存与提醒 + “网络不好，先不扫描”。

## 3. 云端 API 契约（固件对接）

### 3.1 服务器与域名（复用 midyear-workshop 项目）

- 域名：**https://tuvmkt.com**（该项目的 `APP_URL`）；
- 服务器：该项目已部署的境外 VPS（Ubuntu 22.04 + Docker + Nginx + Certbot，`client_max_body_size 300m`）；
- 上传接口：`POST https://tuvmkt.com/api/scan`（**需后端在此项目中新增该路由**，契约见下，固件与后端可并行开发）。

### 3.2 请求

`multipart/form-data`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `image` | JPEG 文件 | 640×480，质量 ~50–70 |
| `deviceId` | string | 设备标识（如 `xzd-t5e1-001`） |
| `action` | string | `in`（放入）/ `out`（取出） |
| `container` | string | `冰箱\|零食柜\|药盒\|调料柜\|主食柜` |
| `timestamp` | string | `2026-08-15 16:00:00` |

### 3.3 响应

```json
{
  "code": 0,
  "data": {
    "items": [
      {
        "name": "光明鲜牛奶",
        "scannedAt": "2026-08-15 16:00",
        "expiryDate": "2026-08-17",
        "daysLeft": 2,
        "suggestedContainer": "冰箱",
        "confidence": 0.92
      }
    ],
    "note": "可选：看不清的部分提示"
  }
}
```

失败：`{"code":1,"msg":"..."}`（固件按非 0 处理为失败，提示重试）。

### 3.4 云端处理（后端负责，固件不关心）

- 后端收到照片 → 调**火山方舟（Volcano Ark）视觉大模型**解析（品名 / 保质期 / 数量 / 建议容器）；
- API Key 用 **midyear-workshop 项目的 `ARK_API_KEY`**（位于 `/Users/lwl/Documents/Projects/midyear-workshop/.env` 与服务器 `.env`，密钥不写入固件，**设备端不持有任何 API Key**）；
- Ark 配置：`ARK_BASE_URL=https://ark.cn-beijing.volces.com/api/v3`；视觉模型建议 `doubao-seed-2-1-turbo-260628`（当前项目 `.env` 的 `ARK_CHAT_MODEL` 为文本模型，图片解析需用视觉模型，以后端实际可用为准）；
- 解析结果写入数据库（复用该项目服务器 + SQLite，新增 `food_items` 表；入库 / 出库 / 容器分类 / 提醒均以后端与软件端为准）。

### 3.5 设备心跳（可选，后端已就绪）

## 6. 改造提示（基于 copy 工程）

- `app_photo.c` 当前逻辑：预览 → 触控定格 5s（仅显示不保存）。改造点：
  1. 触控定格 → 改为 **3s 半透明大数字倒计时**（屏 240×320，倒计时层用半透明 alpha 绘制，数字区域约占半屏）；
  2. 倒计时结束抓帧保存 JPEG（640×480）→ HTTP multipart 上传 `https://tuvmkt.com/api/scan`；
  3. 加【放入 / 取出】待机页与结果页（HTTP 返回 JSON 解析后上屏）；
  4. “咔嚓”走板载音频（或 GPIO 蜂鸣器备选）；
  5. 断网 / 失败分支（§2.4）。
- 网络栈：TuyaOpen 自带 lwip / HTTP client（参考 SDK examples 中 `http` / `netconn` 用法）。

## 7. 字体与字符集（屏显约束，必读）

> 屏幕是 240×320 低分辨率小屏，中文显示**必须用点阵字库，禁止矢量 TTF**。矢量字体在低分辨率下缩放会产生抗锯齿灰阶、丢像素、缺笔画，是糊字 / 毛边元凶。

| 用途 | 点阵规格 |
|---|---|
| 中文正文 / 按钮 / 结果页（品名、日期、保质期等） | **16×16 GB2312 点阵字库（HZK16 格式）**，原样点对点输出，不缩放 |
| 数字 / 字母 / 符号 | 8×16 或 16×16 ASCII 点阵 |
| 倒计时大数字 3→2→1 | 16×16 或 24×24 点阵，**整数倍（×2 / ×3）最近邻放大**，禁止非整数缩放 |

硬性约束：

1. **禁止 TrueType(.ttf) 等矢量字体**：AI 不要拿 ttf 做实时缩放渲染；
2. **禁止抗锯齿、灰度、亚像素渲染**：输出必须是纯 1-bit 二值点阵，每个字符像素严格对齐网格；
3. **字符集限定 GB2312 简体中文 + ASCII**（数字、字母、常用符号），不要全量 Unicode / 生僻字，减小字库体积、避免未知字符乱码碎像素；
4. 字号必须与点阵规格严格匹配：不要拿 12×12 强行放大显示，需要大字用整数倍放大；
5. 倒计时“半透明”仅指**位图字形 + 整数 alpha 混合**（数字背后能看到相机画面），字形本身仍是点阵，不做平滑处理。
