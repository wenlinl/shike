改配置（WiFi / 设备号 / 容器 / 引脚）后，把基准文件复制到各示例文件夹，保持完全一致。

## 帧管线三条铁律（本次修复的核心）

1. **摄像头引脚**：必须用 XIAO ESP32S3 Sense 官方定义（config.h 的 `XIAO_CAM_PIN_*`）。
   此前代码误用 ESP32-S3-EYE 风格引脚（VSYNC/HREF=6/7），会与 I2S 音频（LRC=6/DIN=7）冲突，已全部修复。
2. **条码用灰度、上传用 JPEG**：条码示例统一 GRAYSCALE 抓帧，上传前用 `fmt2jpg` 现场编码 JPEG（04 示例），
   不要在同一份代码里来回切换摄像头格式。
3. **事件检测独立烧录**（03）：灰度帧差与 JPEG 拍照格式冲突，保持单独演示，不并入扫码/上传主循环。

## 设备身份与交互

- 内模组 `DEVICE_ID = shike-xiao-001`（已与外置平板 `xzd-t5e1-001` 分离）。
- **放入/取出由外置平板触屏选择**（与设计基线 §3.1 一致）：
  平板 → `POST /api/device/task`（云端保存当前动作）→ 内模组扫码前 `GET /api/device/task?deviceId=...` 取动作；
  无下发 / 断网时内模组默认"放入"。
- 内模组按键仅作**扫码触发**；断网时按帧记录当时动作，重传不串。
- 上传时间戳来自 NTP（北京时间），不再写死。

> ⚠️ 后端需新增 `POST|GET /api/device/task`（契约见[《后端对接说明》](../docs/03-软件/后端对接说明.md) §9），平板端（T5-E1 app_xzd.c）待机页【放入】【取出】按钮调用 POST 下发。

## 烧录（Arduino IDE）

完整步骤见《[Arduino 环境与条码库接入](../docs/03-软件/Arduino环境与条码库接入.md)》，要点：

1. ✅ 环境已装（2026-08-23）：esp32 2.0.14 + ZXing 库 + C++17，4 个示例编译全部通过；
2. 开发板选 **Seeed XIAO ESP32S3**（`esp32:esp32:XIAO_ESP32S3`）；
3. `esp32-camera` 随板卡包内置，**无需单独装库**；WiFi / HTTPClient 自带；
4. 2.0.x 兼容写法已应用：multipart 整包 POST + `WiFiClientSecure.setInsecure()`（不要用 3.x 的流式 `POST(lambda)` / `http.setInsecure()`）；
5. 端口找不到 / 上传失败：**按住 BOOT 再插 USB** 进入 BootLoader 后重传。
