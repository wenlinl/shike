# 食刻 ShiKe · 冰箱食品保质期智能管理

> Slogan：**食刻在场，不浪费每一份食材**

食刻是一台贴在冰箱上的 AI 食品扫描台：把食品拿到镜头前扫一下，云端 AI 认出它是什么、能放多久，库存自动记账；屏幕、手机端和大屏随时告诉你谁快过期、能做什么菜。

核心链路：**扫（拍照）→ 认（云端视觉 AI）→ 记（库存 ±1）→ 显（屏幕 + H5 + 大屏）**，已作为端到端可演示产品跑通——已有可演示原型机、硬件已烧录、后端已上线、H5/大屏可用、3D 打印外壳完成。

## 问题与机会

- **全球每年约 1/3 的食物被浪费**，中国年浪费超过 1 亿吨；家庭冰箱保有量超 3 亿台。
- 核心痛点：**"放进去就忘"**——临期食品被遗忘、重复购买、过期浪费。
- 现有方案：换整台智能冰箱（成本数千至上万元、渗透率低），或手动录入 App（繁琐、难以坚持）。
- 食刻的机会：**对存量电器进行智能化+AI改造 + 零学习成本**，把食材管理压缩到"一次按键 / 一次经过镜头"。

## 目标人群

- 核心人群：注重健康与性价比的中国家庭，尤其是多口之家（老人/儿童同住）、大城市的独居单身人士、厨房新手与健身人群；
- 延展人群：食堂 / 餐饮 / 药房等 B 端客户（合规盘点需求）；
- 出海方向：日本家庭（食品浪费意识强、包装日期规范，对食材管理需求明确）。

## 理想使用场景

### 场景一：批量采购入库（门内连续扫描，像超市扫码）

买菜回家后一次放入十几件食物，不需要逐件操作：

1. 把贴在**冰箱门外**的磁吸扫描版取下；
2. 贴到**冰箱门内侧**（此时门是开着的，理想情况冰箱门与冰箱呈垂直夹角，镜头正对过门通道）；
3. 点击按钮进入**扫描模式**；
4. 把食物放进冰箱时经过扫描镜头；
5. 镜头自动识别并发出**"滴"的一声**（像超市扫货），屏幕即时显示"已录入：牛奶 ×1"；
6. 关门后设备回到待机，弹出本次汇总"放入 12 件 / 取出 0 件"一次确认。

> 一句话：**买完菜往冰箱里放，经过镜头就自动记账，全程零手动输入。**

### 场景二：单品放入 / 取出（门外单品扫描）

日常临时拿取一件食品：

1. 设备**仍然贴在冰箱上**，无需取下；
2. 点击屏幕进入**扫描模式**；
3. 拿起食物对着镜头扫一下；
4. **立刻上传**云端识别，屏幕显示品名 / 保质期，库存 ±1。

> 一句话：**拿起扫一下，放回已记账。**

### 场景三：日常待机（展示板）

不扫描时设备常显**时钟 + 临期/过期提醒 + 今日菜谱**，按任意键唤醒，是冰箱门上的"第二块屏"。

## 系统架构

```text
┌─ 硬件（T5-E1 单板）──────────────────────┐
│ 摄像头 → 拍照 → HTTPS multipart 上传       │
│ 屏幕显示：识别结果 / 临期提醒 / 操作引导     │
└───────────────┬─────────────────────────┘
                ▼
        POST /api/scan（图片 + deviceId + action）
                ▼
┌─ 云端（已部署 shike.live）────────────────┐
│ 视觉 AI：品名 + 保质期 OCR                  │
│ 业务：库存 ±1 / 成员 / 菜谱 / 购物清单 / 通知 │
│ 存储：SQLite 15 张表（FoodItem / ScanLog / …）│
└───────────────┬─────────────────────────┘
                ▼
┌─ 消费端 ─────────────────────────────────┐
│ 设备屏幕 / H5 手机端 / 大屏 Web             │
└───────────────────────────────────────────┘
```

## 技术栈

| 层 | 技术 |
|---|---|
| 硬件 | T5-E1（SPARKLEIOT T5AI DEV）：ST7789 触控屏 + GC2145 摄像头 + 板载音频 |
| 固件 | TuyaOpen（C，`app_xzd.c`），WiFi 凭据已打码 |
| 视觉 AI | 火山方舟 `doubao-seed-2-1-turbo-260628`（关闭思考），低置信不入库 |
| 后端 | Next.js + Prisma + SQLite，Docker 部署，11 个 API / 15 张表 |
| 前端 | H5（5 Tab）、大屏 Web、硬件交互模拟页 |

## 云架构与 AWS 规划

**当前**：境外 VPS 部署后端（shike.live）+ 火山方舟视觉模型。

**规划（面向规模化与出海）**，整体构建于亚马逊云科技：

- **存储与数据库**：S3（扫描图片）+ DynamoDB / RDS（库存、家庭、设备数据）；
- **AI 能力**：Amazon Bedrock / Amazon Rekognition 提供食品识别与保质期日期 OCR；
- **接入层**：API Gateway + Lambda 支撑扫描请求，Cognito 负责家庭与设备鉴权，CloudFront 加速 H5 与大屏；
- **区域**：首发部署 `ap-northeast-1`（东京），满足日本个人信息保护法（APPI）数据合规，并为欧美扩展预留架构。

## 未来迭代方向

1. **磁吸门版 v2 硬件**：ESP32-S3 单板（BOM ¥70–90），磁吸 + 锂电 + 干簧管，可贴门内/门外两用，比现开发板更小更便宜更贴场景；
2. **门内连续扫描**：开门自动进入扫描模式、自动取景抓帧、批量入队、关门汇总一次确认（对应场景一）；
3. **板端边缘识别 + 本地目录缓存**：已知食品 <0.6 秒免云端，越用越快（家庭重复购买多）；
4. **离线兜底**：关门断网时本地记录，开门窗口自动补传；
5. **商业化基础设施**：设备 Token 鉴权、OTA 升级、多家庭共享、远程查看；
6. **B 端扩展**：食堂 / 餐饮 / 药房合规盘点 SaaS；
7. **出海日本首发**：食品浪费社会共识最强、包装日期体系规范、无外挂扫描台竞品；AWS 东京部署，合规先行；
8. **数据增值**：门内温度修正保质期（DS18B20）、菜谱推荐、购物清单自动生成。
9. **一键补货**：联动生鲜电商 / 商超，库存告急时一键下单补货。
