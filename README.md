# 食刻 ShiKe · 冰箱食品保质期智能管理

> Slogan：**食刻在场，不浪费每一份食材**

食刻是一台贴在冰箱上的 AI 食品扫描台：把食品拿到镜头前扫一下，云端 AI 认出它是什么、能放多久，库存自动记账；屏幕和手机端随时告诉你谁快过期、能做什么菜。

核心链路：**扫（拍照）→ 认（云端视觉 AI）→ 记（库存 ±1）→ 显（屏幕 + H5）**，已作为端到端可演示产品跑通——已有可演示原型机、硬件已烧录、后端已上线、H5 可用、3D 打印外壳完成。

## 问题与机会

- **全球每年约 1/3 的食物被浪费**，中国年浪费超过 1 亿吨；家庭冰箱保有量超 3 亿台。
- 核心痛点：**"放进去就忘"**——临期食品被遗忘、重复购买、过期浪费。
- 现有方案：换整台智能冰箱（成本数千至上万元、渗透率低），或手动录入 App（繁琐、难以坚持）。
- 食刻的机会：**对存量电器进行智能化+AI改造 + 零学习成本**，把食材管理压缩到"一次按键 / 一次经过镜头"。

## 理想使用场景

### 场景一：批量采购入库（门内连续扫描，像超市扫码）

买菜回家后一次放入十几件食物，不需要逐件操作：

1. 在**冰箱门外**的外置平板上点【放入】（指令下发门内模组）；
2. 开门，把食品在门口对着内模组镜头停一下（理想情况镜头正对过门通道）；
3. 内模组**条码本地解码**（无码走视觉兜底），发出**"叮 + 品名"**语音；
4. 连续扫多件，无需逐件确认（像超市收银台）；
5. 关门后系统结算本次会话，外置平板亮起汇总"放入 12 件 / 取出 0 件 / 待确认 N 件"，一次确认或逐条修正。

> 一句话：**买完菜往冰箱里放，门口扫一下就自动记账，关门一次确认。**

### 场景二：单品放入 / 取出（门外单品扫描）

日常临时拿取一件食品：

1. 开门，拿起食品在门口对着内模组镜头停一下（设备无需取下）；
2. 条码本地解码 / 视觉兜底，**"叮 + 品名"**语音播报；
3. 外置平板同步显示品名 / 保质期，库存 ±1；
4. 识别失败时在外置平板 / App 手动确认（US-76）。

> 一句话：**拿起在门口停一下，放回已记账。**

### 场景三：日常待机（展示板）

不扫描时外置平板低功耗待机（**PIR 接近唤醒 + 30 秒自动熄屏**），亮屏显示**时钟 + 临期/过期提醒 + 今日菜谱**，是冰箱门上的"第二块屏"。

## 系统架构

```text
┌─ 硬件（双模组分体）───────────────────────┐
│ 外置平板（T5-E1）：触屏交互 / 库存 / 汇总确认 │
│ 内模组（XIAO ESP32-S3）：条码本地解码 + 视觉 │
│   兜底 → 语音播报 → 事件/结果 HTTPS 上传     │
└───────────────┬─────────────────────────┘
                ▼
        POST /api/scan（条码结果 / 图片 + deviceId + action）
                ▼
┌─ 云端（已部署 shike.live）────────────────┐
│ 查库 / 精修：品名 + 保质期（火山方舟兜底）     │
│ 业务：库存 ±1 / 成员 / 菜谱 / 购物清单 / 通知 │
│ 存储：SQLite 15 张表（FoodItem / ScanLog / …）│
└───────────────┬─────────────────────────┘
                ▼
┌─ 消费端 ─────────────────────────────────┐
│ 外置平板 / H5 手机端                        │
└───────────────────────────────────────────┘
```

## 技术栈

| 层 | 技术 |
|---|---|
| 硬件 | 双模组分体：外置平板 T5-E1（ST7789 触控屏 + 板载音频）+ 内模组 XIAO ESP32-S3 Sense（OV3660 摄像头 + 麦克风 + 功放） |
| 固件 | 外置平板 TuyaOpen（C，`app_xzd.c`）+ 内模组 Arduino（esp32-camera / ZXing），WiFi 凭据已打码 |
| 视觉 AI | 本地条码（ZXing，ms 级）+ 本地 YOLO 品类（≤500ms）+ 云端查库（火山方舟 `doubao-seed-2-1-turbo-260628`），低置信不入库 |
| 后端 | Next.js + Prisma + SQLite，Docker 部署，11 个 API / 15 张表 |
| 前端 | H5（5 Tab）、硬件交互模拟页 |

## 未来迭代方向

> 注：HW-v1 双模组分体、门内连续扫描、本地优先识别（条码 + YOLO）、离线队列均已进入设计与样机冲刺（架构见内部文档《设计基线》）。

1. **HW-v1 量产工程化**：定制双模组 PCB、OV5640 AF 驱动、外壳 / 磁吸 / pogo、认证（PSE / TELEC / FCC）、试产；
2. **原生 App / 小程序**：补齐汇总三通道的"严重差异推送"，家庭共享深化；
3. **商业化基础设施**：设备 Token 鉴权、OTA 升级、多家庭共享、远程查看；
4. **数据增值**：门内温度修正保质期（DS18B20）、营养报告、菜谱推荐、购物清单自动生成；
5. **B 端扩展**：食堂 / 餐饮 / 药房合规盘点 SaaS；
6. **出海日本首发**：食品浪费社会共识最强、包装日期体系规范、无外挂扫描台竞品；云侧东京区域部署，合规先行；
7. **一键补货**：联动生鲜电商 / 商超，库存告急时一键下单补货。
